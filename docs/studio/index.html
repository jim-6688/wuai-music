01 / 为什么存在

不另起炉灶，是把现有系统测量化

实验室和“从零搞研发”最大的区别，是已经有研究者拿不到的实验对象：一条真实可测的播放链路、一个 195 GB、4569 文件的真实中文曲库，以及一台能长期采集本机反馈的小光 AI。别人要搭这套台子得先买设备、攒数据、养样本；我们现成。

“咱们做的功能准确吗？都是真实专业的吗？还是纸老虎？” 工作室的起点，是一次不哄不贬的功能真实性审计。
02 / 主攻痛点与论证

把功能拆成三级，用证据说话

不吹牛，也不一棍子打死。下面每一条都对着代码和实测，而不是功能列表。

真金 · 有硬证据

对内的基建

真实实现，敢亮细节。

  • 曲库落盘：4569 文件 / 195 GB，双端逐路径比对 0 失败
  • 封面与索引：155 落盘封面 + 1070 缓存图 0 截断，MPD 索引 3001 首
  • 硬件 ID：整机指纹，换配件跟着变
  • 感知音量曲线、密码恢复出厂
  • DSD / ReplayGain 标注诚实，非位流不冒充
半真 · 证据链有洞

解析真，边界要认清

实现是真的，但生成与整理能力要如实标注。

  • 逐字歌词：真移植，改由大模型现场生成，不取第三方歌词
  • 封面整理：改用本地生成候选，不再刮削第三方
  • CamillaDSP：真实现，但明确非 bit-perfect
纸老虎 · 名不副实

对外的招牌

喊得最响的，恰恰最经不起追问。

  • bit-perfect 假绿灯：读不到硬件证据就默认判直通
  • “智能”心情分类：实为关键词打分，曲库零真标签
  • “源数量”数字好看，但不等于歌词可用
  • 硬件 ID “授权激活”：ID 真，激活未落地
核心判断：对外的招牌基本是纸老虎，对内的基建基本是真金——错位才是痛心的根源。

去纸老虎化第一步很具体：假绿灯改“待验证”而不是默认绿、hw_params 只读当前启用的那一路、把信号链实测数据沉淀成可导出的证据。让“透明”从口号变成能亮出来的东西。

✓ 已落地（2026-11-21）：上面三步已在 T1S 参考机上线——无硬件证据显示“待验证”；播放只读当前输出 hw_params，实测板载 S16_LE @ 44.1 kHz 直通、24bit 源 S32_LE @ 96 kHz 无重采样、DSD64 解码为 S32_LE @ 192 kHz，DTS 5.1 则诚实标降混 2.0；USB DDC 已接入，能力探测读到 PCM 44.1–768 kHz / 原生 DSD / 异步传输；并提供 /api/signal-chain 证据快照与 CSV 导出，任何人可复算。

03 / 三大主攻方向

文件 → 比特 → 听觉，一条链

三个方向不是三个项目，是同一条信号链上的三段。都有现成基础，不是从零起。

DIRECTION 01

小光 AI 神经网络引擎 + 智能声场

起步阶段：先本地学习，后期主力发展

小光 AI 神经网络引擎是后期主力方向，目前仍处起步阶段：纯本地标准库实现，不联网、不下载模型；只学本机正反馈，权重写侧车文件。先用它给十境调音出建议，再延伸到房间声场；短期仍以规则冷启动为主，样本够了才切神经推理。

切入点：本地样本 → 权重侧车 → 十境建议
DIRECTION 02

bit-perfect 与信号链透明

最先：成本最低、最能立信誉

把 analyze_playback 从“声明”变“证据”：每步采样落盘——源规格、解码、重采样、hw_params 实测、时间戳；无证据标“待验证”，导出 JSON / CSV 任何人可复算。USB DDC 已接入，设备能力实测到 PCM 44.1–768 kHz / 原生 DSD / 异步传输，播放路径对比继续做。

第一份产出：《信号链透明白皮书》
DIRECTION 03

本地曲库智能化整理

居中：产品价值最快

文本优先、指纹兜底：时长交叉验证淘汰误匹配，激进清洗脏文件名，先锁专辑再配曲目；每确认对一首，就沉淀一条“指纹/时长/文件名 → 元数据”的本地映射。识别对一首，数据飞轮长一格。

自有资产：中文曲库映射数据集

07 / 深度研究

把讨论沉淀成方法，把方法写成文章

下面每一条都是一轮追问后的判断，不是功能介绍。成型的会写成可复现的研究文章，持续追加。

架构判断

数播像「重造」而非「升级」，根因是缺平台无关的核心层

数播不跑 Flutter，歌词/封面/元数据/心情只能复刻，真正共享的只有 HTTP API、MPD 协议与 MOOD 标签三处契约。一半重造是必然且正确（J1900 跑不动 Flutter、会破坏 bit-perfect），缺的另一半是当初埋在 lib/features 里、没沉淀成独立层的平台无关核心逻辑。

道与术

bit-perfect 修「说的能不能对」，核心价值建「说的能不能信」

USB DDC 已接入并完成能力实测，是术；可验证 + 懂中文曲库才是值得长期投入的道。二者共享同一份数据底座——信号链实测数据与曲库语义数据，走同一个「采集 → 沉淀 → 导出」结构。低频高杠杆，不搞大干快上。

方法诊断

AcoustID 匹配「同一段录音」，而整理要问「哪一首歌」

中文曲库难，不是没数据，是文本脏加缺少交叉验证——目标错配才是根因。路线是文本优先、指纹兜底：时长交叉验证淘汰误匹配、激进清洗文件名、先锁专辑再配曲目；歌词交给大模型生成，从根上不碰第三方歌词版权。已写成研究文章。

信任机制

无证据不是通过，是「待验证」

bit-perfect 只认 ALSA hw_params 实测，读不到就标琥珀色问号，绝不给无实测支撑的绿灯。这项判定已重做并上线，附 JSON / CSV 证据导出，任何人可复算。已写成白皮书。

阅读白皮书 01 →
听感调音

把 PEQ 的三个参数翻译成十个听感维度，语义与专业必须互斥

十境不是十段均衡换皮：语义层用固定频点与 Q 值，把「冷暖／下潜／齿音」这类听感描述映射成滤波器；专业层保留完整十段参数，作为测量校正的落点。两层同时生效会重复处理同一频段，所以做成互斥而不是叠加。参数级验证见白皮书 02。

阅读白皮书 02 →
链路实测

DSD 直出不是开关问题，是这条链路的物理边界

参考机链路为 USB → USB DDC → 75Ω 同轴 → 有源音箱（PCM9211 全数字输入）。S/PDIF 承载不了 native DSD，接收端也不认 DoP；逐项实测后只有 PCM 有声，因此默认关闭 DoP 并保留重采样。结论只对这条链路成立，换接口必须重测——宁可写「不支持」，也不给没有实测支撑的绿灯。

实测验证

白皮书 02：十境调音 8 项配置级验证通过

零处理直通、晨昏 +100 的 180 Hz −6 dB 与 6 kHz +6 dB 反向搁架、深潜 +50 的 70 Hz +5 dB、圆润 +80 的 3 kHz Q4.0 +6.4 dB，加上语义／专业互斥、旧配置兼容与旋钮往返误差小于 1，8 项配置级验证全部通过。听感盲听仍待做。

阅读白皮书 02 →
后期主力

小光 AI 神经网络引擎：起步阶段，尚未成型

纯本地标准库 MLP，不联网、不下载模型，权重与样本只写本机侧车；样本不足时走规则冷启动，够了才切神经推理，并给出每个预设的概率与信心。当前先落在十境建议上，后期作为主力方向继续发展。

08 / 诚实边界

把丑话说前面，免得又成纸老虎

不碰这三样

  • 流媒体授权：门槛在商务资质，谈不动，不在实验室射程内。
  • 自研大算法：声场那块用成熟测量 + PEQ 工程闭环，不做算法军备竞赛。
  • 从第三方歌词库取文本：本质是复制内容，接口再稳也背着版权风险；我们改由大模型现场生成。
诚实代价：数据飞轮冷启动慢、头几个月覆盖率低；语义数据靠“用户确认”喂养，所以产品机制必须让人愿意确认——不能悄悄改库。
