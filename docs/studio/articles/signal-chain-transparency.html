白皮书 01：把 bit-perfect 从「声明」变成「证据」

一次不哄不贬的功能审计，逼出了一个可复算的信号链判定方法。这是工作室的第一篇产出。

信号链透明 吾爱高保真音频工作室 · 2026-11-20

一、问题：绿灯是亮的，证据是空的

审计时我们问了一句很朴素的话：界面上那个亮着的 bit-perfect 绿灯，是真的吗？逐代码追下去，答案让人不安——判定读的是 MPD 的 status.audio，也就是解码器“声明”自己输出的是什么规格，而不是声卡真正跑在什么参数上。两件事在多数时候一致，但在重采样、多卡、输出未打开等情形下会悄悄分家。

更糟的是两个叠加的缺陷：read_hw_params() 遍历所有声卡，取第一个有参数的卡（多卡就读错）；而一旦读不到硬件参数（输出未打开、采样尚未开始），代码落进 else 分支，默认判成 bit-perfect。结果是——最没有证据的时刻，灯反而是绿的。

纸老虎 · 判定 对外喊得最响的招牌，恰恰最经不起追问。这是工作室起点那句“还是纸老虎？”最具体的答案。

二、立判据：真源只有一个

方法学上第一步不是写代码，是把“什么叫证据”钉死。我们定下的判据很硬：bit-perfect 只认 ALSA hw_params 的实测——声卡在 /proc/asound/ 里报告的格式、采样率、声道，才是最终事实。MPD 的声明、配置文件的 format 字段、界面上的文案，都只是旁证，不能单独点亮绿灯。

这条判据带来一个反直觉但正确的结果：没有证据，不等于通过，而是“待验证”。宁可显示琥珀色的问号，也不给一个没有实测支撑的绿灯。

三、方法：每一步都可复算

  1. 只读当前启用路。从 MPD 配置里解析 enabled=yes 的 audio_output，把 hw:PCH,0 这样的设备名映射到 /proc/asound/<card>/pcm<N>p/sub<S>/hw_params。多卡不再读错。
  2. 源规格与实测规格逐项对照。status.audio 给出源采样率/位深/声道，hw_params 给出声卡实际值。一致且无重采样才可能直通；采样率不符判 resample，多声道降混判 downmix，ReplayGain 开启则明确标注非严格直通。
  3. 全程留证并导出。新增 GET /api/signal-chain 证据快照，带时间戳、原始 status.audio、原始 hw_params 文本、启用输出与最终判定，并支持 ?format=csv 导出。任何人拿去可复算。

四、边界：还不够格叫终点

这是第一步，不是答案。三点如实说明：其一，DDC 尚未到货，I²S / USB 与板载卡的真实差异还没跑过对比实验——到货前后各测一遍，才是这篇的续集。其二，插上 DDC 后 policy=one 仍会锁在板载、不自动启用也不弹窗，这个坑按既定节奏等实测再动。其三，CamillaDSP 路径本身就不是 bit-perfect，方法已把它明确归类，不冒充直通。

“bit-perfect 修的是‘说的能不能对’；核心价值建的是‘说的能不能信’。本篇属于前者。”— 工作室方法论笔记
